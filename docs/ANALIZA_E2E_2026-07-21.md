## 1. Znaleziska — żywa ścieżka (priorytetowo)

### H1 (HIGH) — Dashboard raportuje zamrożone equity przy otwartej pozycji
`status_handler.py:46-54`: KPI equity = `portfolio["realized"]`, a `realized` jest
zamrażane przy wejściu w pozycję (`portfolio.py:51`) i aktualizowane dopiero przy
zamknięciu. Bot jest trend-follower long-only — w pozycji siedzi miesiącami; nagłówkowe
equity/total_return może kłamać przez cały rajd/krach, sprzecznie z poprawnymi
(mark-to-market) wierszami decyzji niżej na tej samej stronie. Stan zawiera wszystko
do policzenia MTM (`side`, `entry_fill`, `entry_equity`, `last_price`) — fix czysto
w handlerze statusu, zero kontaktu ze strategią. **Ryzyko: błędna ocena bramki M5.**

### M1 (MEDIUM) — Log decyzji best-effort, ciche trwałe luki
`bot.py:81-82` zapisuje stan, potem `bot.py:98-117` dopisuje decyzję w try/except
tylko-logującym (`:116-117`). Dwa tryby utraty: (a) `append_decision` rzuca → połknięte
→ Lambda sukces → zero SNS; (b) timeout/crash między save a append → retry widzi
`last_bar == latest_time` → „skipped" → decyzja dla tego bara NIGDY nie powstanie.
Log decyzji to jawnie surowiec metryk M5 (`state_store.py:12-15`) — luki cicho psują
Sharpe/DD/PF. Lokalnie już zaobserwowano brak bara 2026-07-19 w
`paper_state/BTCUSDT_1d.decisions.jsonl` (cron lokalny co 6h, inna przyczyna, ale
ten sam skutek). **Przed oceną bramki M5 zweryfikować kompletność logu w DynamoDB.**

### M2 (MEDIUM) — Niewykrywalna śmierć bota (brak heartbeat + brak DLQ)
Jedyny alarm to `Errors ≥ 1` z `treat_missing_data = "notBreaching"`
(`infra-serverless/main.tf:303-316`). Wyłączony schedule, zepsuta rola schedulera,
błąd dostarczenia po stronie EventBridge → zero metryki Errors → zero alertu, bot
flatline na zawsze. Scheduler ma retry (3×/1h) ale brak `dead_letter_config`
(`main.tf:190-198`) — po 3 porażkach event znika. Fix: alarm `Invocations < 1`/24-25h
z `treat_missing_data = "breaching"` + SQS DLQ na targcie schedule'a (~10 linii TF).

### M3 (MEDIUM) — Brak guardu minimalnej historii: krótka odpowiedź Binance = przymusowe zamknięcie pozycji
`feed.py:40-41` odrzuca tylko PUSTĄ odpowiedź; `Strategy.target_positions`
(`strategy.py:52-53`) zeruje pierwsze `warmup=100` barów. Odpowiedź ≤100 wierszy →
`target=0` → `reconcile` zamyka żywego longa z fee+slippage, normalny „traded", bar
oznaczony jako przetworzony — błędny, bezalertowy, nieodwracalny trade. Fix jednolinijkowy:
`len(df) < warmup+margines → raise` (zamienia to w retry+alarm).

### Niższe (żywa ścieżka)
- **L1/M — konwencja fill:** silnik backtestu wykonuje sygnał[t] po **open[t+1]**
  (`engine.py:148-154`), bot po **close[t]** (`bot.py:79-80`). Na 24/7 crypto różnica
  ~bps i NIE jest to lookahead, ale test równoważności (`test_paper_trading.py:18-34`)
  napędza portfel konwencją SILNIKA — dowodzi parytetu księgowości, nie timingu bota.
  Docstringi („cannot diverge") obiecują więcej niż testy stwierdzają. Udokumentować +
  domknąć testem; istotne dla bramki „tracking error <10%" i przejścia na realne $.
- **L2 — okno EMA 399 barów** vs pełna historia w backteście: residual wagi ~3.4e-4,
  przy `min_separation=0.0` nożowy crossover może teoretycznie flipnąć o dzień. Akceptowalne.
- **L3 — brak optimistic lockingu stanu** (`state_store.py:82-88` bezwarunkowy put) —
  problem tylko przy ręcznym invoke współbieżnym z cronem, scheduler sam tego nie zrobi.
- **L4 — fee/slippage z persystowanego stanu nadpisują config** (`portfolio.py:102-111`)
  — zmiana `--fee` po powstaniu stanu nie działa. Gotcha, dziś wartości zgodne.
- **L5 — nieograniczony item stanu** (pełna lista trades w jednym itemie, limit 400KB
  ≈ ~2000 trades ≈ dekady). Notatka.
- **M — brak catch-up po pominiętym dniu:** `step()` przetwarza tylko najnowszy bar —
  crossover w pominięty dzień handluje ~24h później po innej cenie niż backtest.

## 3. Backtester i testy

**Rdzeń silnika bez zarzutu** (zweryfikowane linia po linii, 16/16 testów zielone):
brak lookahead (pending → open[t+1], testowane exact-value), księgowość poprawna
i konserwatywna, force-close na końcu danych uczciwy, Sharpe unit-safe (rok 365d,
spacing z mediany), maxDD/CAGR poprawne, walk-forward z 4 układami foldów + sweep fee
(M4_EDGE_VALIDATION) metodologicznie uczciwy, anty-gaming (pesymistyczny SL-przed-TP,
blokada re-entry, Donchian bez bieżącego bara) zrobiony dobrze. Wszystkie skrzywienia
(force-close per fold, fee od pełnego equity) w bezpieczną stronę — zaniżają edge.

**Problemy:**
- **M (uśpiony → HIGH przy włączeniu SL): gap-optimism stop-lossa** — stop fills po
  dokładnej cenie stopu nawet gdy bar przeskoczył ją gapem (`engine.py:159-171`).
  Nieużywany w prod (bot bez SL), ale przyszły run z `--sl` da optymistyczne liczby.
- **M — CLI backtestu nie umie odtworzyć configu produkcyjnego:** `build_strategies()`
  hardkoduje EMA 20/50 z shortami (`backtesting/run.py:27-31`), prod to 20/100 long-only;
  brak `--fast/--slow` — weryfikacja „backtest = live" dla dokładnych parametrów wymaga
  edycji kodu.
- **M — luki testowe:** `PaperBot.step` (żywa pętla!) zero testów; brak bezpośredniego
  testu sygnału `EmaCrossover` na spreparowanych świecach; brak testów metryk (a bramki
  M5 = Sharpe/DD/PF liczone TYMI funkcjami); brak testów `data.py`/`feed.py`/DynamoDB
  store'a end-to-end.
- **M-L — zero walidacji integralności danych:** brak checków NaN/gap/high≥low w
  loaderze i feedzie; zepsuty CSV płynie cicho do EMA i metryk.
- **L — PF liczony na frakcjach zwrotów netto**, nie dolarowym P&L (`metrics.py:86-88`)
  — bramka „PF ≥ 1.3" jest zdefiniowana wg tej konwencji, stosować konsekwentnie.
- **L — walkforward:** cichy fallback `combos[0]` gdy wszystko odpadnie na `min_trades`.

## 4. Infra / CI / higiena

**Solidne:** IAM least-privilege (bot: 3 akcje na 1 ARN; status: read-only), cron
poprawny, PITR włączony, retencja logów ustawiona, alarm Errors→SNS (subskrypcja
POTWIERDZONA wg tfstate), sekrety: nie istnieją i nie są potrzebne (keyless public
Binance + role IAM), gitleaks full-history w CI z rotowanym kluczem, CI testuje
dokładnie żywe pakiety na Pythonie 3.11 = runtime Lambdy.

**Braki:**
- **M — tfstate tylko lokalnie** (laptop), S3 backend opisany w komentarzu
  `main.tf:8-12` ale bucket nie istnieje; stan obejmuje już DNS/ACM/CloudFront —
  odtworzenie boli. Migracja lub minimum: kopia do `~/TradePulse_safety` po każdym apply.
- **M — deploy path nietestowany:** `build_lambda_package.sh` nigdy w CI (hardkoduje
  `.venv/bin/pip`), zip niepinowany (`pip install requests` bez wersji — build
  niereprodukowalny; warstwa pandas jest pinowana, OK). Fix: pin `requests==`,
  job CI: build → unzip → smoke-import handlera.
- **L — function URL publiczny (auth NONE)** — świadoma decyzja D7, leakuje tylko
  paper-dane; residua: obejście cache CloudFront = invoke+2 ready na request (brak

  może dawać sporadyczne 502. Kosmetyka przy tym ruchu.
- **L — brak lint/typecheck; filtr path w tests.yml pomija test_state_store.py**
  (push tylko na ten plik nie odpala CI); brak `terraform fmt/validate` w CI.
- **L — martwe artefakty w repo:** `Dockerfile.fix`, `NAPRAWA.md`, `APP_MONITOR.py`

  (11 .tf — footgun: apply byłby destrukcyjny). Zarchiwizować na branchu.
- **L — monolityczny `requirements.txt` stale+CVE** (`requests==2.31.0`,
  `tensorflow==2.16.1`...) — nigdzie nie zdeployowany, los = los monolitu po M5.
- **INFO — domena tradepulseai.co.uk wygasa 2026-09-29** — 2,5 tyg. PO bramce M5
