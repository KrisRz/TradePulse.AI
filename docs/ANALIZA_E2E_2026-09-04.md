## WERDYKT

**Żywa ścieżka jest spójna od giełdy do strony — każdy szew zweryfikowany u źródła
zgadza się z sąsiadem.** Feed → sygnał → log decyzji → księga → egzekucja → stan →
API → strona dają TE SAME liczby (bar, cena, target, equity, fille), log decyzji jest
kompletny na obu kanałach (51/51 i 174/174, zero luk), 3 fille w DynamoDB to
dokładnie 3 zlecenia na giełdzie (id, cena, ilość), infra w Terraformie == AWS
(`plan` bez zmian na obu rootach), alarmy → SNS → e-mail POTWIERDZONE (subskrypcja
CONFIRMED, historia pokazuje realne odpalenie i wygaszenie 06–07.08).

**Trzy rzeczy, których E2E nie potwierdza, i to jest wynik, nie ozdoba:**
1. **Kanał 4h — ten, który pójdzie na prawdziwe pieniądze — nie ma działającego
   sprawdzenia parytetu księgowego.** `gate.py --fidelity` jest napisane pod 1d:
   `WINDOW_START` zaszyte na 2026-07-16, a replay idzie ścieżką modelowaną.
   Na 4h drukuje FAIL 348 rozjazdów — artefakt narzędzia, ale luka jest realna.
2. **Rozjazd, który ten FAIL mierzy, to znana, świadomie odłożona luka prowizji**
   — teraz z liczbą: `realized` zapisane 200,00 vs replay 199,80 = dokładnie
   0,1% × 200 na każdym wejściu. Księga 4h nie księguje prowizji; model tak.
3. **Lambdy nie mają `event_invoke_config`** → domyślne 2 retry asynchroniczne
   są aktywne. To potwierdza PRZESŁANKĘ CRITICAL-2 z audytu kodu (zlecenie przed
   zapisem `last_bar` + retry = re-trade bara). Dziś nie wystąpiło (0 błędów/14 dni),
   ale mechanizm jest uzbrojony.

## 2. Znaleziska E2E (nowe względem audytu kodu; priorytetowo)

### E1 (MEDIUM) — Kanał 4h nie ma działającego parytetu księgowego; narzędzie bramki A jest 1d-only
- `gate.py:71` `WINDOW_START = date(2026, 7, 16)` zaszyte → kryterium 6
  (infrastruktura) liczy 21 dni „bez wywołania" PRZED istnieniem venue (06.08).
- Kryterium 5 (replay) odtwarza księgę ścieżką **modelowaną** (fee 0,1% do equity),
  a żywa księga 4h idzie ścieżką **ilościową** (fee w BNB → `fees_external`, nie
  w equity) → 348 „rozjazdów", każdy = $0,15–0,20.
- Skutek: **kanał, który pójdzie na live, nie ma sprawdzenia „księga == replay"**,
  a to jedyne kryterium bramki A, które łapie błędy księgowania (nie sygnału).
- **Fix (M5-safe, nie dotyka Lambd):** `--window-start` per kanał (domyślnie
  = pierwszy `decision#`), replay ścieżką ilościową z `fill#` jako źródłem filli i
  prowizji; wtedy niezaksięgowana prowizja BNB staje się **mierzoną liczbą w
  raporcie** (dziś: $0,60 przez 3 fille), a nie FAIL-em.

### E2 (LOW) — Origin `/api/state` publiczny bez CloudFront; „cache ogranicza origin do ~1/min" nie zachodzi
- `infra-site/api.tf:76-104`: function URL `authorization_type = "NONE"` +
  permission `principal = "*"`; bezpośrednie wywołanie URL-a Lambdy = HTTP 200.
- Read-only i tanie (GetItem/Query), ale rachunek jest ograniczony tylko dla ruchu
  przez CloudFront. **Fix:** OAC dla Lambda function URL (`AWS_IAM` + CloudFront
  Origin Access Control, provider 6.x to umie) — ~10 linii TF w `infra-site/`,
  zero kontaktu z M5.
- Drobiazgi dokumentacyjne: plan mówi „CSP `connect-src 'self'`" — realnie
  dochodzi `api.binance.com` + `wss://stream.binance.com` (wykres na żywo) i
  `bot.` (dashboard 1d); cache `/api/state` to 30 s, nie 60 s.

### E3 (MEDIUM, potwierdzenie) — Retry asynchroniczny Lambdy jest aktywny (brak `event_invoke_config`)
- `get-function-event-invoke-config` → brak na `paper-bot`, `shadow-bot`,
  `venue-4h` → AWS domyślnie **2 retry** po błędzie funkcji, do tego Scheduler 3×.
- Samo w sobie pożądane (transjentne 5xx Binance), ALE w połączeniu z „zlecenie
  przed `_save`" (`bot.py:120` vs `:162`) daje re-trade bara — CRITICAL-2 audytu
  kodu. **Nie wyłączać retry; naprawić kolejność (odczyt filli PRZED decyzją).**

### E4 (INFO) — Pierwszy fill (06.08 21:11) nie ma `mark_at_order` ani snapshotu salda
- Bramka C: C1/C2 liczone z 2/3 filli, C5 2/3 — pierwszy fill był backfillowany
  (`scripts/backfill_venue_fill_20260806.py`) przed `measure_drift`. Zaksięgowane,
  nie ukryte (narzędzie samo to raportuje). Bez akcji; 20/20 i tak wymaga ~10 mies.

### E5 (INFO) — Zegar dowodów
- 1d: 51 decyzji, 0 RT → bramka B `INCONCLUSIVE_EXTEND` 10.09 z konstrukcji.
- 4h: 174 decyzji, 1 RT zamknięty (−1,03%), 1 otwarty (+21,8% MTM), 3/20 filli.
- Shadow: 30 sond, ostatnie 20 zleceń na venue to wyłącznie heartbeaty (0,00012 BTC).
